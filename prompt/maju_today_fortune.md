# 마주(MAJU) — 오늘의 운세 메인 배너 노출 로직

> **용도**: 메인 탭 상단에 유저별 "오늘의 연애운"을 짧은 배너 형태로 노출하기 위한 계산·갱신 로직 명세서
> **연관 문서**: maju*report_prompt_spec*수정.md (연간 리포트, 세운 관계 로직 재사용)
> **버전**: 1.0.0

---

## 1. 개요 및 배치 방식 선택

연간 리포트(`섹션3_올해연애운`)는 유저 1인당 1회, AI(Claude API) 호출로 생성한다.
반면 오늘의 운세는 **전체 활성 유저 대상 매일 재생성**되어야 하므로, 다음 이유로 **AI 호출이 아닌 규칙 기반(결정론적 lookup) 방식**을 채택한다.

- 매일 자정 전체 유저에 대해 API를 호출하면 비용·지연이 선형으로 증가함
- 오늘의 운세는 "일간(日干) × 오늘의 일진(日辰)" 관계만으로 결정되는 값이라 유저별 사주 원본 데이터(십성/오행 개수)까지 필요하지 않음 → 순수 관계 테이블 lookup으로 충분
- 문구 다양성은 레벨별 문구 풀에서 시드 기반 로테이션으로 확보 (AI 없이도 반복감 최소화)

즉, 오늘의 운세 = **배치 잡(1일 1회) + DB 캐싱 + 클라이언트 단순 조회** 구조로 운영한다.

---

## 2. 노출 위치 및 UI 형태

- **위치**: 메인 탭 최상단 배너 (프로필 카드 리스트 위)
- **형태**: 아이콘 + 레벨 배지 + 1줄 문구 (20~30자 내외)
- **탭 동작**: 배너 탭 시 연간 리포트가 아닌, **"오늘의 운세 상세 리포트"** 화면으로 이동 (섹션 10 참고). 연간 리포트로의 진입은 별도 마이페이지/리포트 탭에서 유지
- **노출 대상**: 가입 완료 전체 유저. 사주 입력(생년월일, 성별)은 온보딩 필수 단계이므로 별도 조건 분기가 필요 없다. 시주(태어난 시간) 입력 여부만 무관 — 일진 계산은 연/월/일 기준이므로 시주 미입력자도 동일하게 노출 가능

## 3. 입력 데이터

```
[유저 저장 데이터 — 온보딩 시 확정, 변경 없음]
- 일간(日干): user.ilgan            (갑/을/병/정/무/기/경/신/임/계)
- 일간 음양: user.eumyang           (양간 | 음간)
- 일지(日支): user.ilji
- 월지(月支): user.wolji

[매일 계산되는 값 — 만세력 라이브러리로 산출]
- 오늘 일진 천간: todayIljin.cheongan
- 오늘 일진 지지: todayIljin.jiji
```

> 만세력 계산은 별도 라이브러리(예: 기존 사주 입력 시 사용한 절기/음력 변환 로직)를 그대로 재사용한다. 본 문서는 계산된 오늘의 일진 값을 입력으로 받는 지점부터 다룬다.

## 4. 일간 - 오늘 일진 관계 판정

연간 리포트의 "일간-세운 관계" 판정 로직과 동일한 방식을 **세운 대신 오늘의 일진**에 적용한다.

```typescript
interface DailyRelation {
  cheonganHap: boolean; // 천간 합
  cheonganChung: boolean; // 천간 충
  jijiHap: boolean; // 지지 합
  jijiChung: boolean; // 지지 충
  saeng: boolean; // 생 관계 (오늘 일진이 일간을 생)
  geuk: boolean; // 극 관계 (오늘 일진이 일간을 극)
  bihwa: boolean; // 비화
}
```

판정 기준(합충생극 테이블)은 연간 리포트 스펙의 "일간-세운 관계" 절과 완전히 동일한 오행/십성 상생상극표를 사용하므로 별도 재정의하지 않는다.

## 5. 레벨 산출

연간 리포트의 "에너지 레벨 결정" 표를 재사용하되, 상반기/하반기/연말 구분이 없으므로 **단일 컬럼**으로 축소한다.

| 관계 유형 | 오늘 레벨 |
| --------- | --------- |
| 천간 합   | HIGH      |
| 천간 충   | LOW       |
| 지지 합   | HIGH      |
| 지지 충   | LOW       |
| 생 관계   | HIGH      |
| 극 관계   | LOW       |
| 비화      | MID       |

### 복수 관계 동시 해당 시

같은 날 천간·지지 관계가 동시에 성립할 수 있으므로(예: 천간 합 + 지지 충) 연간 리포트와 동일한 가중 평균 방식을 적용한다.

```
HIGH = 2, MID = 1, LOW = 0
평균값 = 해당 관계들의 점수 합 / 해당 관계 개수
반올림 후: 1.5 이상 → HIGH, 0.5 이상 → MID, 미만 → LOW
```

관계가 하나도 해당하지 않는 예외 상황(이론상 비화라도 항상 하나는 성립)은 발생하지 않지만, 안전장치로 아무 관계도 true가 아니면 `MID`로 기본 처리한다.

## 6. 배너 문구 카탈로그

레벨별로 5개의 문구 풀을 두고, **날짜 + userId를 시드로 한 결정론적 로테이션**을 적용해 같은 유저가 매일 다른 문구를 보되, 재계산해도 같은 날엔 항상 같은 문구가 나오도록 한다.

> **LOW 레벨 문구 설계 원칙**: LOW를 있는 그대로("연애운이 낮다")만 전달하면 유저가 앱을 닫는 방향으로 작용해 인앱 액션 전환에 부정적 영향을 줄 수 있다. 따라서 LOW 문구는 **"오늘은 어렵지만, 행운의 아이템과 함께 극복해보자"** 톤으로 설계하고, 섹션 10-2에서 계산되는 `행운의아이템` 값을 문구 안에 삽입해 자연스럽게 상세 리포트 진입(탭)을 유도한다. HIGH/MID는 기존과 동일하게 유지한다.

| 레벨 | 문구 풀                                                        |
| ---- | -------------------------------------------------------------- |
| HIGH | ① 오늘은 인연의 기운이 강해요, 대화를 먼저 걸어보세요          |
| HIGH | ② 설렘 지수 최고! 오늘 만남에 적극적으로 움직여보세요          |
| HIGH | ③ 좋은 인연의 신호가 보이는 하루예요                           |
| HIGH | ④ 오늘 대화한 사람, 눈여겨봐도 좋아요                          |
| HIGH | ⑤ 연애운이 상승하는 날, 먼저 다가가 보세요                     |
| MID  | ① 잔잔하지만 안정적인 하루예요                                 |
| MID  | ② 서두르지 않아도 괜찮은 하루예요                              |
| MID  | ③ 평소처럼 자연스럽게 흘러가는 날이에요                        |
| MID  | ④ 무리한 기대보단 편안한 마음이 필요한 날                      |
| MID  | ⑤ 관계를 천천히 알아가기 좋은 하루예요                         |
| LOW  | ① 오늘은 흐름이 살짝 느려요, {아이템}과 함께 가볍게 극복해봐요 |
| LOW  | ② 컨디션이 낮은 날이지만, {아이템}이 기분을 바꿔줄 거예요      |
| LOW  | ③ 잠깐 주춤하는 하루, {아이템}으로 분위기를 환기해보세요       |
| LOW  | ④ 오늘은 나를 먼저 다독여야 할 때, {아이템} 하나면 충분해요    |
| LOW  | ⑤ 가라앉기 쉬운 하루예요, {아이템}과 함께 이겨내봐요           |

```typescript
function pickBannerText(
  level: "HIGH" | "MID" | "LOW",
  userId: string,
  dateStr: string,
  luckyItem: string // 섹션 10-2에서 산출된 행운의 아이템 (LOW일 때만 삽입에 사용)
): string {
  const pool = BANNER_TEXT_POOL[level]; // 5개 문구 배열
  const seed = hash(`${userId}-${dateStr}`); // 결정론적 해시 (예: djb2, murmur 등)
  const idx = seed % pool.length;
  const template = pool[idx];
  return level === "LOW" ? template.replace("{아이템}", luckyItem) : template;
}
```

> 배치 잡 실행 순서: **행운의 아이템(섹션 10-2) 계산 → 레벨 산출(섹션 5) → 배너 문구 생성(LOW인 경우 아이템 삽입)** 순으로 처리해야 하므로, 섹션 7의 배치 잡 순서도 이에 맞춰 조정한다(섹션 7-보완 참고).

> **조사 결합 유의사항**: `{아이템}` 자리에 들어가는 문구(예: "붉은 계열의 립스틱이나 소품")는 마지막 글자 받침 유무에 따라 뒤따르는 조사(이/가, 을/를, 과/와)가 달라진다. 섹션 10-2의 5개 아이템 문구는 모두 받침 있는 명사로 끝나도록 통일해 "이", "과" 조사만 사용하면 문법 오류 없이 삽입되도록 설계했다. 아이템 문구 풀을 추가·수정할 경우 이 받침 규칙을 유지하거나, 받침 유무를 판별해 조사를 동적으로 붙이는 유틸 함수를 별도로 둔다.

## 7. 배치 잡 & 캐싱 구조

```
[매일 00:00 KST 배치]
1. 오늘 날짜의 일진(천간/지지) 계산 — 1회만 계산 (전체 유저 공통 값)
2. 오늘 일진 천간의 오행 기준 행운의 아이템 산출 (섹션 10-2) — 유저 무관, 1회만 계산
3. 전체 활성 유저 순회
   a. user.ilgan, user.eumyang, user.ilji, user.wolji 조회
   b. 오늘 일진과의 관계(DailyRelation) 판정
   c. 레벨 산출 (섹션 5)
   d. 문구 선택 (섹션 6, 시드 기반 / 레벨이 LOW면 2에서 산출한 행운의 아이템을 문구에 삽입)
   e. dailyFortuneCache 테이블에 upsert (배너 문구 + 상세 항목 동시 저장)
4. 배치 완료 후 캐시 조회 API 활성화

[클라이언트 조회 시 — 실시간 계산 없음]
GET /api/daily-fortune/me
→ dailyFortuneCache 테이블에서 (userId, date=오늘) 조회 후 반환
```

### 온보딩 완료 시 온디맨드 생성 (가입 당일 노출)

사주 입력은 온보딩 필수 단계이므로, 자정 배치를 기다리지 않고 **온보딩(사주 입력) 완료 시점에 해당 유저 1인분만 즉시 계산**해 캐시에 적재한다. 계산 로직은 배치 잡의 2~3단계(관계 판정 → 레벨 산출 → 문구 생성)와 완전히 동일하며, "오늘의 일진"과 "행운의 아이템"은 이미 당일 배치에서 공통 값으로 계산돼 있으므로 재사용한다.

```
[온보딩 완료 이벤트 트리거]
1. user.ilgan, user.eumyang, user.ilji, user.wolji 저장 완료
2. 오늘의 일진 / 행운의 아이템 공통 캐시 조회 (당일 배치 결과 재사용, 없으면 즉시 계산 후 공통 캐시에 저장)
3. 해당 유저의 DailyRelation 판정 → 레벨 산출 → 문구 생성
4. dailyFortuneCache 테이블에 upsert
→ 가입 직후 메인 탭 진입 시 바로 배너 노출
```

### 캐시 스키마

```typescript
interface DailyFortuneCache {
  userId: string;
  date: string; // "YYYY-MM-DD" (KST 기준)
  level: "HIGH" | "MID" | "LOW";

  todayIljin: { cheongan: string; jiji: string };
  createdAt: Date;
}
```

## 9. 연간 리포트와의 관계 정리

| 구분      | 연간 리포트 (섹션3\_올해연애운) | 오늘의 운세 (본 문서)          |
| --------- | ------------------------------- | ------------------------------ |
| 생성 방식 | Claude API (AI 생성)            | 규칙 기반 lookup (배치)        |
| 생성 주기 | 유저 요청 시 1회                | 매일 00:00 전체 유저 일괄      |
| 판단 기준 | 일간-세운(연간 천간·지지) 관계  | 일간-일진(오늘 천간·지지) 관계 |
| 결과 단위 | 상반기/하반기/연말 3구간        | 오늘 1구간                     |
| 노출 위치 | 리포트 상세 화면                | 메인 탭 배너                   |

두 로직은 "일간 기준 관계 판정 → 레벨 매핑 → 텍스트 매핑"이라는 동일한 구조를 공유하므로, 추후 관계 판정 함수(합충생극 판별 로직)를 공통 모듈로 분리해 재사용하는 것을 권장한다.

## 10. 배너 탭 시 "오늘의 운세" 상세 리포트 (v2 — 리텐션 강화 개편)

배너는 연애운 한 줄만 보여주지만, 탭하면 오늘 하루를 여러 각도에서 풀어주는 상세 리포트로 이동한다. 경쟁 운세 서비스(포스텔러, 점신 등)는 총운을 게이지·점수로 보여주고 항목을 세분화하는 공통 패턴이 있어, 이를 참고하되 **정보 소비에서 끝나지 않고 앱의 핵심 행동(매칭 탭 이동)으로 연결**되도록 재설계했다. 신규 API 호출 없이 기존 계산값(DailyRelation, 연간 리포트 캐시)만으로 파생하므로 배치 방식은 그대로 유지된다.

### 10-1. 리포트 구성 항목 (v2)

| 순서 | 항목                  | 판단 기준                                              | 비고                                         |
| ---- | --------------------- | ------------------------------------------------------ | -------------------------------------------- |
| 1    | 총운 게이지           | 섹션 10-1a의 0~100점 점수 + 레벨                       | 배너와 동일 레벨 사용, 점수만 신규 산출      |
| 2    | 애정운                | 섹션 5의 가중 평균 레벨 (배너와 동일 값)               | 배너 문구 그대로 재사용                      |
| 3    | 새로운 인연운         | 지지 관계만 별도 판정                                  | 지지 합 → HIGH / 지지 충 → LOW / 그 외 → MID |
| 4    | 오늘의 궁합 좋은 상대 | 연간 리포트(`섹션2_이상형유형.끌리는유형`) 캐시 재사용 | 신규 계산 없음, CTA로 매칭 탭 연결           |
| 5    | 행운의 아이템         | 오늘 일진 천간의 오행                                  | 오행 매핑표 (10-3)                           |

> **v1 대비 변경**: 애정운·대인관계 통합 항목을 다시 "애정운"과 "새로운 인연운"으로 분리(경쟁 서비스처럼 항목을 세분화해 정보 밀도를 높임). "오늘의 궁합 좋은 상대"를 신규 추가해 정보 소비 후 매칭 탭으로 자연스럽게 넘어가도록 CTA를 배치. "오늘의 한마디"는 검토 후 제외(단순 문구 반복으로 판단, 정보 가치 낮음).

### 10-1a. 총운 게이지 점수 산출

배너/애정운 판정에 쓰는 섹션 5의 가중 평균(HIGH=2, MID=1, LOW=0)을 0~100점 스케일로 환산해 게이지에 사용한다.

```typescript
function calcTotalScore(weightedAvg: number): number {
  // weightedAvg: 0~2 범위의 가중 평균값 (섹션 5)
  return Math.round((weightedAvg / 2) * 100);
}

// 레벨 임계값도 동일 비율로 환산
// 75점 이상 → HIGH, 25점 이상 → MID, 미만 → LOW (기존 1.5/0.5 기준의 100점 환산)
```

### 10-2. 오늘의 궁합 좋은 상대

연간 리포트 생성 시 이미 AI로 산출해둔 `섹션2_이상형유형.끌리는유형`(유형명, 설명, 태그)을 그대로 가져와 노출한다. 별도 계산이나 API 호출이 없으므로 배치 비용 증가가 없다.

- 노출 문구: `"{유형명} 스타일과 잘 맞는 하루예요"` + 태그 최대 3개
- CTA 버튼: "지금 둘러보기" → 매칭 추천 탭으로 이동 (특정 필터링 없이 탭 이동만, 매칭 로직은 `maju_matching_pool_spec.md` 그대로 사용)

## 11. UI 요청사항 정리

### 11-1. 메인 탭 배너

- 위치: 메인 탭 최상단, 프로필 카드 리스트 위
- 구성: 레벨 배지(HIGH/MID/LOW) + 1줄 문구(20~30자) + 우측 화살표(탭 유도)
- 레벨별 배지 색상: HIGH는 강조색, MID/LOW는 중립색(톤 다운)으로 구분
- 노출 대상: 가입 완료 전체 유저 (사주 입력은 온보딩 필수라 별도 조건 없음, 시주 입력 여부만 무관)
- 가입 당일부터 즉시 노출 (온보딩 완료 시점에 온디맨드로 계산, 배치 대기 없음)

### 11-2. 배너 탭 인터랙션

- 탭 시 "오늘의 운세 상세" 화면으로 이동 (연간 리포트와는 별도 화면)
- 연간 리포트 진입 경로는 마이페이지/리포트 탭에서 별도 유지

### 11-3. 오늘의 운세 상세 화면 (v2)

- 상단: 뒤로가기 + 타이틀("오늘의 운세") + 오늘 날짜
- 노출 항목 (위에서 아래 순서)
  1. 총운 게이지 바 (점수 + 레벨)
  2. 애정운 카드: 레벨 배지 + 문구
  3. 새로운 인연운 카드: 레벨 배지 + 문구
  4. 오늘의 궁합 좋은 상대 카드: 유형명 + 태그 + "지금 둘러보기" CTA 버튼 (매칭 탭 이동)
  5. 행운의 아이템 카드
  6. 공유하기 버튼 (운세 카드 이미지 공유)
- "오늘의 한마디" 항목은 제외 (단순 반복 문구로 정보 가치가 낮다고 판단)
- 카드 스타일: 배너와 통일된 톤(레벨 배지 색상 규칙 동일 적용)

### 11-4. LOW 전용 처리 및 공통 원칙

- 배너/상세 문구 모두 "{행운의 아이템}과 함께 극복하자" 톤으로 노출 (이탈 방지, 전환 유도)
- HIGH/MID는 톤 변경 없음
- 문구 내 아이템 삽입 시 조사(이/가, 과/와) 오류 없도록 아이템 문구는 받침 있는 명사로 통일
- 배너 문구와 상세 화면 문구는 동일한 값 재사용 (별도 문구 생성 없음 → 일관성 유지)
- 하루 동안은 새로고침해도 동일 문구 노출 (날짜+userId 기준 고정)
- 레벨 배지는 3단계(HIGH/MID/LOW)만 사용, 추가 세부 등급 없음
